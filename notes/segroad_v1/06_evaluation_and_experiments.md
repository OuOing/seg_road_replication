# Seg-Road 学习笔记：评估、实验与数据划分

本篇汇总模型评估、论文实验和数据划分知识。详细的训练代码与术语仍保留在 `05_training_pipeline.md`，这里主要用于快速复习。

## 1. 评估闭环

```text
模型 logits
-> sigmoid 得到置信度
-> threshold 得到 0/1 mask
-> 和真实 mask 比较
-> 统计 TP、FP、FN、TN
-> 计算 Precision、Recall、F1、IoU
```

### 1.1 四种结果

```text
TP：预测道路，真实也是道路
FP：预测道路，真实是背景
FN：预测背景，真实是道路
TN：预测背景，真实也是背景
```

道路断裂主要增加 `FN`；把屋顶、阴影等误判为道路主要增加 `FP`。

### 1.2 常用指标

```text
Precision = TP / (TP + FP)
Recall    = TP / (TP + FN)
IoU       = TP / (TP + FP + FN)
F1        = 2 * Precision * Recall / (Precision + Recall)
```

直觉：

```text
Precision：不要乱报道路
Recall：不要漏掉道路
F1：Precision 和 Recall 都要兼顾
IoU：预测道路和真实道路的区域重叠程度
```

### 1.3 IoU 和 MIoU

```text
IoU_road：只计算道路类别
MIoU：对道路和背景等所有类别的 IoU 取平均
```

背景像素通常很多，因此看道路提取效果时不能只看 Accuracy 或 MIoU，还应单独关注 `IoU_road`、Recall 和 F1。

## 2. 阈值

`threshold=0.5` 是常用起点，不一定是最优值。

```text
降低阈值：更容易预测道路，Recall 可能提高，FP 可能增加
提高阈值：预测更谨慎，Precision 可能提高，FN 可能增加
```

更合适的做法是在验证集上测试多个阈值，选择 IoU 或 F1 较好的值，不能反复根据测试集调整。

## 3. Baseline、SOTA 与消融实验

### 3.1 Baseline

`Baseline` 是参考模型，用来回答新方法比基础方案提升了多少。

### 3.2 SOTA

`SOTA` 是 `State Of The Art`，表示特定数据集、指标和时间范围内的先进水平，不是永久称号。

### 3.3 Ablation Study

`Ablation Study` 是消融实验：保持其他条件不变，一次移除或替换一个模块。

针对 Seg-Road，可以比较：

```text
CNN baseline
CNN + Transformer
CNN + PCS
CNN + Transformer + PCS
```

这样才能分别分析 Transformer 的全局建模贡献和 PCS 的连通性监督贡献。

### 3.4 公平比较

需要尽量保持：

```text
相同数据集划分
相同输入尺寸
相同训练轮数
相同优化器和学习率策略
相同评价代码
相同阈值或阈值选择规则
```

还要同时观察参数量、FLOPs、FPS 和显存，而不是只看最高精度。

## 4. 数据集划分

### 4.1 三种数据集

```text
train：用于更新模型参数
validation：用于选择模型和超参数
test：用于最终客观评价
```

测试集不能反复用于调整学习率、阈值或网络结构，否则测试结果会失去客观性。

### 4.2 道路数据为什么容易泄漏

遥感道路数据经常先把一张大图裁成多个小块。如果先裁剪再随机划分，来自同一张大图的相邻区域可能分别进入训练集和验证集：

```text
同一城市大图
-> patch A 进入训练集
-> 相邻 patch B 进入验证集
```

由于两个 patch 的道路纹理、建筑、颜色和拍摄条件非常相似，模型可能已经间接见过验证区域，导致验证分数虚高。

这种问题叫 `Data Leakage`（数据泄漏）。

### 4.3 更合理的划分顺序

优先按照原始大图、城市或地理区域划分：

```text
先划分原始大图或区域
-> 再分别裁剪 train、validation、test
```

而不是：

```text
先把所有大图裁成 patch
-> 再把所有 patch 随机打乱划分
```

### 4.4 当前代码的局限

当前 `code/train.py` 使用文件级随机划分：

```text
全部图片/patch
-> 随机打乱
-> 按 val_ratio 划分
```

它适合最小训练验证，但正式复现实验应提供明确的训练集和验证集列表，或者根据原始大图/区域分组划分，避免相邻 patch 泄漏。

## 7. Patch、Stride 与遥感图像裁剪

### 7.1 什么是 Patch

`Patch` 指从一张大图中裁出来的小图块。

例如原始遥感图：

```text
1500 x 1500
```

模型训练尺寸：

```text
512 x 512
```

因此需要把大图裁成多个 `512 x 512` 的 patch，再送进模型。

### 7.2 为什么要裁剪

主要原因：

```text
GPU 显存无法一次处理超大图片
模型通常要求 batch 中图片尺寸一致
裁剪后可以得到更多训练样本
局部道路细节更容易保留
```

但裁剪也有缺点：跨越 patch 边界的道路上下文可能被截断。

### 7.3 什么是 Stride

`Stride` 在裁剪中表示滑动窗口每次移动多少像素。

例如：

```text
patch_size = 512
stride = 512
```

表示每次移动 512 像素，patch 之间基本不重叠。

如果：

```text
patch_size = 512
stride = 256
```

表示每次只移动 256 像素，相邻 patch 会有 256 像素重叠。

### 7.4 重叠裁剪的作用

重叠裁剪可以：

```text
减少道路恰好被 patch 边界截断的影响
让同一区域从不同上下文中被观察
推理时减轻拼接边缘的不连续
```

代价是：

```text
patch 数量增多
训练和推理计算量增加
相邻 patch 内容高度相似
```

### 7.5 为什么相邻 Patch 容易造成数据泄漏

如果先把所有大图裁成大量重叠 patch，再随机划分训练集和验证集，两个几乎相同的区域可能被分到不同集合。

例如：

```text
训练 patch：覆盖 x=0 到 512
验证 patch：覆盖 x=256 到 768
```

两者有一半区域完全相同。模型在训练时已经看到验证 patch 的一部分，因此验证指标会虚高。

### 7.6 正确的划分策略

更安全的流程：

```text
原始大图或城市区域
-> 先划分 train / validation / test
-> 每个集合内部再裁剪 patch
```

如果数据来自多个城市，可以按城市划分：

```text
城市 A、B、C -> train
城市 D       -> validation
城市 E       -> test
```

这种划分更能检验模型能否泛化到新的地理区域。

### 7.7 推理时如何拼回大图

对大图滑窗预测后，需要把 patch 结果放回原位置。

如果 patch 不重叠，可以直接拼接；如果存在重叠，可以对重叠位置的概率取平均，再统一阈值化：

```text
多个 patch 的 probability
-> 重叠区域求平均
-> 得到整张大图 probability map
-> threshold
-> 完整道路 mask
```

这通常比先把每个 patch 二值化再拼接更平滑，因为概率保留了更多信息。

本节记住：

```text
Patch 是小图块，stride 是滑动距离。
stride 小于 patch size 时会产生重叠。
必须先按大图或区域划分数据，再在各集合内部裁剪。
```

## 8. DeepGlobe、Massachusetts 与数据分布

### 8.1 为什么要用多个数据集

只在一个数据集上表现好，不能说明模型适用于所有遥感图像。

使用多个数据集可以观察：

```text
模型是否能适应不同地区
模型是否能适应不同拍摄条件
模型是否能适应不同道路外观
```

第一篇论文使用了 DeepGlobe 和 Massachusetts 两个道路数据集进行实验。

### 8.2 什么是空间分辨率

`Spatial Resolution`（空间分辨率）描述图像中一个像素对应现实世界多大的区域。

例如：

```text
0.5 m 分辨率：一个像素大约对应地面 0.5 m 的范围
1.0 m 分辨率：一个像素大约对应地面 1.0 m 的范围
```

数值越小，通常表示地面细节越清晰。同样宽度的道路，在不同空间分辨率下可能占据不同数量的像素。

### 8.3 为什么空间分辨率会影响模型

如果道路宽度在现实中约为 4 米：

```text
0.5 m 分辨率 -> 约占 8 个像素
1.0 m 分辨率 -> 约占 4 个像素
```

分辨率较低时，道路变得更细，边界和连接关系更难判断：

```text
道路可能只剩几列像素
小路容易消失
道路边界更模糊
PCS 标签更容易受到像素误差影响
```

### 8.4 什么是 Domain Shift

`Domain Shift`（领域偏移）指训练数据和测试数据的分布不同。

道路提取中的领域差异可能来自：

```text
不同城市或国家
不同卫星或航空相机
不同空间分辨率
不同季节和光照
不同道路材料
不同建筑、植被和阴影
```

例如：

```text
训练集：晴天、城市道路、清晰图像
测试集：阴天、乡村道路、较低分辨率
```

即使道路任务相同，模型也可能表现下降。

### 8.5 训练集和测试集的分布关系

理想情况是：

```text
训练集和测试集任务相同
但测试图像没有被训练见过
```

这可以检验模型的泛化能力。

如果训练集和测试集差异过大，低分不一定完全说明模型结构不好，也可能说明领域偏移很强。

### 8.6 为什么论文结果不能直接照搬

论文报告的 IoU、F1 等数字依赖完整实验条件：

```text
数据集版本
训练/验证/测试划分
图像裁剪方式
输入尺寸
数据增强
模型规模
损失权重
阈值和评价代码
```

当前项目记录的论文数字是论文报告值，不代表本地代码已经复现这些结果。

### 8.7 读数据集介绍时关注什么

```text
图像数量和尺寸
训练集、验证集、测试集如何划分
空间分辨率
mask 的编码方式
是否需要裁剪
是否存在不同区域或城市
官方评价指标是什么
```

本节记住：

```text
多个数据集用于检验泛化。
空间分辨率决定道路在像素中有多粗。
Domain Shift 解释了为什么换地区或传感器后性能可能下降。
```

## 9. 图像预处理与标签编码

### 9.1 什么是预处理

`Preprocessing`（预处理）指把原始文件转换成适合模型计算的形式。

```text
原始 JPG / PNG
-> 读取
-> 调整尺寸
-> 转换数据类型
-> 归一化
-> 调整维度顺序
-> 送进模型
```

训练和推理必须尽量使用相同的预处理，否则模型输入分布会发生变化。

### 9.2 归一化

普通 8 位图片像素范围是：

```text
0 到 255
```

当前 Dataset 中使用：

```python
image_array = image_array / 255.0
```

得到：

```text
0 到 1
```

这叫 `Normalization`（归一化）。数值范围变小后，优化器通常更容易稳定工作。

### 9.3 标准化

`Standardization`（标准化）是另一种处理方式，常见形式是：

```text
new_value = (value - mean) / std
```

其中：

```text
mean：均值
std：标准差
```

归一化和标准化不是同一件事：

```text
归一化：把数值缩放到固定范围，例如 0 到 1
标准化：让数据大致均值为 0、标准差为 1
```

如果使用预训练 backbone，通常需要遵循该 backbone 规定的 mean 和 std；当前项目的最小实现先采用 0 到 1 归一化。

### 9.4 标签编码

道路 mask 通常是灰度 PNG，但文件中的道路像素可能编码为：

```text
0：背景，255：道路
```

模型训练需要的标签通常是：

```text
0：背景，1：道路
```

因此代码中使用：

```python
mask_array = (mask_array > 0).astype(np.float32)
```

这一步叫 `Label Encoding`（标签编码），把原始像素值转换成类别值。

### 9.5 为什么 mask 不能当普通图片处理

图像 resize 可以使用双线性插值，因为颜色可以取中间值；mask 是类别标签，不能随意产生新类别。

```text
图像：BILINEAR
mask：NEAREST
```

如果 mask 是多类别分割，还必须确认每个整数值对应哪个类别，不能只简单判断大于 0。

### 9.6 类别不平衡

`Class Imbalance`（类别不平衡）指不同类别的像素数量差异很大。

道路图中常见：

```text
背景像素：很多
道路像素：较少
```

这会带来一个问题：如果模型大量预测背景，整体 loss 或 Accuracy 可能看起来还不错，但道路 Recall 很差。

应对思路包括：

```text
使用 pos_weight
使用 Dice Loss 或 Focal Loss
裁剪时增加含道路区域的 patch
关注 IoU、Recall、F1，而不只看 Accuracy
```

当前 `SegRoadLoss` 支持 `pos_weight_seg` 和 `pos_weight_con`，但默认没有额外设置，需要根据真实数据统计后再决定。

### 9.7 数据增强也必须保持标签同步

对图片做翻转时，mask 必须做完全相同的翻转：

```text
image 左右翻转
mask 也左右翻转
```

不能只翻转图片，否则图片和标签空间位置不再对应，模型会学到错误监督。

PCS 标签应在增强后的 mask 上重新生成，而不是继续使用增强前的 PCS 标签。

本节记住：

```text
图像和 mask 的预处理规则不同，但空间变换必须同步。
训练和推理的数值预处理必须一致。
道路像素较少时，要警惕类别不平衡。
```

## 10. Dice Loss 与 Focal Loss

### 10.1 为什么 BCE 可能不够

道路分割中背景像素通常远多于道路像素。普通 BCE 如果平均所有像素的错误，背景像素可能占据主要影响：

```text
背景预测得很好
道路预测得很差
总 BCE 仍可能看起来不高
```

因此有时需要更关注前景区域和难分类像素。

### 10.2 Dice 系数

`Dice Coefficient`（Dice 系数）衡量预测区域和真实区域的重叠：

```text
Dice = 2 * TP / (2 * TP + FP + FN)
```

它和 F1 在二分类区域分割中形式相同。

`Dice Loss` 通常写成：

```text
Dice Loss = 1 - Dice
```

预测道路和真实道路重叠越好，Dice 越大，Dice Loss 越小。

### 10.3 Dice Loss 的特点

Dice Loss 直接关注前景和预测区域的重叠，不会像普通 Accuracy 那样被大量背景完全掩盖。

优点：

```text
适合前景较少的分割任务
直接关注区域重叠
对道路断裂和区域缺失比较敏感
```

局限：

```text
单个像素的概率监督不如 BCE 直接
batch 或空 mask 情况需要小心数值稳定
通常与 BCE 组合使用
```

### 10.4 Focal Loss

`Focal Loss`（聚焦损失）会降低容易分类样本的影响，把注意力放到难分类样本上。

直觉：

```text
背景很容易判断为背景 -> 不要让它占据全部 loss
道路边界、阴影区域、断裂位置 -> 重点关注
```

它通常包含一个调节因子，让高置信度且正确的样本权重变小。

### 10.5 BCE、Dice、Focal 的分工

```text
BCE：逐像素监督，训练稳定
Dice：关注整体区域重叠，缓解前景少
Focal：关注难分类样本，减少容易样本主导
```

可以组合成：

```text
total_loss = BCE + beta * DiceLoss
```

或者：

```text
total_loss = FocalLoss + beta * DiceLoss
```

`beta` 是人为设置的损失权重，也属于超参数。

### 10.6 为什么当前先使用 BCEWithLogitsLoss

当前项目处于学习和最小复现阶段，先使用：

```text
seg_loss = BCEWithLogitsLoss(seg_out, seg_target)
con_loss = BCEWithLogitsLoss(pcs_out, pcs_target)
total_loss = seg_loss + alpha * con_loss
```

这样可以先把：

```text
logits
目标标签
梯度
联合损失
```

这些核心概念跑通。之后可以加入 Dice 或 Focal，并通过消融实验判断是否真的提升验证集表现。

### 10.7 空道路 mask 的数值问题

如果某张 patch 中完全没有道路：

```text
TP = 0
FP = 0
FN = 0
```

直接计算 Dice 可能出现除以 0，因此实现时通常加入很小的 `epsilon`：

```text
Dice = (2 * TP + epsilon)
       / (2 * TP + FP + FN + epsilon)
```

这叫 `Numerical Stability`（数值稳定性）处理。

本节记住：

```text
BCE 看逐像素错误，Dice 看区域重叠，Focal 看难分类样本。
先用 BCE 跑通，再用消融实验验证更复杂损失是否有价值。
```
