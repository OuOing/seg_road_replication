# Strip Convolution 与重参数化

## 1. 为什么 decoder 需要条带卷积

普通方形卷积在方形窗口内同时观察道路和两侧背景。道路通常细长、连续、方向多变，
因此作者在 decoder 使用长条卷积，让感受野更贴近道路形状。

```text
1x13：沿水平方向聚合
13x1：沿垂直方向聚合
旋转后的 1x13 / 13x1：覆盖两种斜向结构
```

条带卷积不是可变形卷积：

```text
GroupDCN：采样点由 offset 动态移动
Strip Conv：卷积核位置固定，但形状细长且覆盖多个方向
```

## 2. 旧式斜向条带卷积的问题

论文 Figure 10 中的旧方法大致通过：

```text
padding
-> reshape / 拉伸特征
-> 竖直条带卷积
-> reshape / crop 恢复
```

来间接得到斜向卷积效果。作者认为反复拉伸和缩放会改变像素之间的相对位置，可能引入
感知误差。

## 3. SegRoadV2 的实现

新方法使用：

```text
原特征
-> padding
-> rotation
-> 水平和垂直条带卷积
-> inverse rotation
-> clip / 恢复原尺寸
```

核心直觉：先把斜路旋转成接近水平或垂直方向，再用 `1x13`、`13x1` 处理，最后旋转
回来。相比旧式 reshape，作者强调该方法不改变特征的相对位置关系。

## 4. 训练时的四个分支

论文公式 8：

```text
O = conv_1x13(I)
  + conv_13x1(I)
  + invtrans(conv_1x13(trans(I)))
  + invtrans(conv_13x1(trans(I)))
```

其中：

```text
I：输入特征
O：输出特征
trans：padding + rotation
invtrans：inverse rotation + 恢复尺寸
conv：卷积加 BatchNorm
```

四个分支对应：

```text
原方向的水平条带
原方向的垂直条带
旋转方向的第一条斜向条带
旋转方向的第二条斜向条带
```

训练时保留多分支，模型可以分别学习不同方向的道路特征。

## 5. 第一层重参数化：融合 Conv 和 BatchNorm

卷积可以写成：

```text
z = W * x + B
```

推理阶段 BatchNorm 使用固定统计量：

```text
BN(z) = gamma * (z - mu) / sigma + beta
```

代入卷积结果：

```text
BN(Conv(x))
= gamma * (W*x + B - mu) / sigma + beta
```

重新整理：

```text
W' = gamma / sigma * W
B' = gamma / sigma * (B - mu) + beta
```

因此：

```text
BN(Conv(x)) = Conv'(x)
```

训练结束后，可以把每个分支的 Conv 和 BatchNorm 融合成一个带新权重 `W'`、新偏置
`B'` 的卷积。输出在浮点误差范围内保持等价。

实现时框架通常使用：

```text
sigma = sqrt(running_var + eps)
```

不能漏掉 BatchNorm 的 `eps`。

## 6. 第二层重参数化：合并 1x13 和 13x1

原方向两个分支已经各自融合 Conv+BN：

```text
W1：1x13
W2：13x1
```

把它们用 0 填充到共同的 `13x13`：

```text
1x13 放在 13x13 的中间横行
13x1 放在 13x13 的中间竖列
其他位置填 0
```

然后直接相加：

```text
W = pad(W1) + pad(W2)
B = B1 + B2
```

因为卷积是线性运算：

```text
Conv(W1, x) + Conv(W2, x)
= Conv(W1 + W2, x)
```

所以水平、垂直两个分支可以变成一个十字形有效权重的 `13x13` 卷积。

旋转后的两个斜向分支也按相同原则合并。最终：

```text
训练时：4 个条带卷积分支
推理时：2 个 13x13 卷积计算
```

## 7. 为什么合并后可能更快

重参数化的主要收益是把复杂训练图变成更规则的推理图：

```text
分支更少
算子调用更少
中间张量和同步更少
规则卷积更容易使用硬件优化内核
```

但不能简单说 FLOPs 一定下降。论文明确指出，受硬件优化影响，两个 `13x13` 卷积在
实际测试中比四个 `13x1` 类分支更快，即使理论计算量未必更小。

因此需要分别报告：

```text
Params
FLOPs
真实 latency
峰值显存
```

| `(1,64,128,128)` | 170.62 / 8.02 | 139.23 / 1.49 |

这里的新结构在论文统计中同时降低了参数量和 MFLOPs；重参数化后的真实推理速度仍应
在目标硬件上单独测量。

## 9. 为什么只放在 decoder

作者把条带卷积主要放在 decoder，用于恢复道路形状和细节，并给出两点考虑：

```text
大量放入 encoder 可能拖慢推理
通用数据集的目标形状未必符合条带卷积的优势
```

对道路提取而言，decoder 正在从多尺度特征恢复细长结构，因此更适合使用方向性卷积。

## 10. 和其他模块的分工

```text
DSA：全局关系，可变形 query
GroupDCN：局部几何，可变形采样点
Strip Conv：多方向细长感受野
PCS：直接监督相邻像素连通关系
```

一句话：

```text
DSA 找道路走向，GroupDCN 修局部形状，Strip Conv 沿道路方向恢复细节，PCS 约束连接。
```

## 11. 复现时的验证

除了分割指标，还应验证重参数化前后输出是否等价：

```text
model.eval()
同一个输入分别通过训练结构和部署结构
检查 max_abs_error 和 mean_abs_error
```

然后分别计时，预热后统计多次推理的中位数或均值。只有输出误差足够小且实测延迟下降，
才能说明部署转换正确且确实有价值。
